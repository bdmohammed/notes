📦 1. What is an Array?

An Array is a reference-type object that acts as a fixed-size container storing multiple values of the same data type under a single variable name.

🔑 Key Characteristics

PropertyDetail
📦 Storage TypeReference Type — object lives in the Heap
🔒 SizeFixed after creation — this is a known disadvantage
🔢 IndexingStarts at 0, ends at length - 1
🎯 ElementsHomogeneous — same data type only

📌 Quick Memory Example

int[] arr = {10, 20, 30}; Index → 0 1 2 Value → 10 20 30

🔬 3. Internal Memory Model

🏗️ Stack vs Heap

int[] arr = {10, 20, 30, 40, 50}; STACK (Reference) HEAP (Object Data) ┌──────────────────┐ ┌─────────────────────────────────┐ │ arr [ref/addr] ├────▶│ [10] [20] [30] [40] [50] │ └──────────────────┘ │ 0 1 2 3 4 ← index │ │ 100 104 108 112 116 ← addr │ └─────────────────────────────────┘ Each int = 4 bytes, contiguous!

⚡ Why O(1) Random Access?

FormulaMath
// Direct address calculation — no traversal needed! address of arr[i] = base_address + (i × size_of_type) // Example: arr[3] arr[3] = 100 + (3 × 4) = 112 ✅ direct jump!
🎯
Interview Question: "Why is array access O(1)?" — Answer: Elements are stored contiguously in memory. The address of any element is calculated in constant time using the formula above. No iteration required.

🔑 Key Facts

  • arr → reference variable stored on the Stack
  • Actual array data → stored in the Heap
  • Default value for int[] is 0
  • Printing arr gives something like [I@3e25a5 (class name + hashcode)

🧠 Multiple Variable Declarations — Tricky!

DeclarationDimensionsValid?
int[] a, b;a→1D, b→1D✅ Valid
int[] a[], b;a→2D, b→1D✅ Valid
int[] []a, b;a→2D, b→2D✅ Valid

⚠️
Rule: Extra dimension before variable name is only allowed for the first variable in a declaration. Subsequent variables cannot use this syntax.

📐 6. Multi-Dimensional Arrays

🧠 Jagged Arrays — Java's Superpower!

Unlike C/C++, Java allows rows in a 2D array to have different lengths — called Jagged Arrays.

Jagged ArrayJava
int[][] arr = new int[2][]; // 2 rows, column sizes TBD arr[0] = new int[3]; // row 0 has 3 elements arr[1] = new int[5]; // row 1 has 5 elements ✅

🗺️ Example 1 — 2D Jagged (rows: 3 + 2)

int[][] a = new int[2][]; a[0] = new int[3]; a[1] = new int[2]; ┌─────┬─────┐ a ──▶ │ • │ • │ └──┬──┴───┬─┘ │ │ ┌───┘ └──────┐ ▼ ▼ ┌───┬───┬───┐ ┌───┬───┐ │ 0 │ 0 │ 0 │ │ 0 │ 0 │ └───┴───┴───┘ └───┴───┘ a[0] (size 3) a[1] (size 2)

🗺️ Example 2 — 3D Jagged

3D Jagged ArrayJava
int[][][] a = new int[2][][]; a[0] = new int[3][]; a[0][0] = new int[1]; a[0][1] = new int[2]; a[0][2] = new int[3]; a[1] = new int[2][2];
┌─────┬─────┐ a ──▶ │ • │ • │ (Top-level: 2 slots) └──┬──┴───┬─┘ │ │ ┌─────────────┘ └───────────────┐ ▼ ▼ [a[0]] [a[1]] ┌───┬───┬───┐ ┌───┬───┐ │ • │ • │ • │ │ • │ • │ └─┬─┴─┬─┴─┬─┘ └─┬─┴─┬─┘ │ │ │ │ │ ┌───┘ │ └──────┐ ┌───┘ └───┐ ▼ ▼ ▼ ▼ ▼ ┌─┐ ┌─┬─┐ ┌─┬─┬─┐ ┌─┬─┐ ┌─┬─┐ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ └─┘ └─┴─┘ └─┴─┴─┘ └─┴─┘ └─┴─┘ (1) (2) (3) (2) (2) ◄──────────────────────────────────────────────────▶ 3rd level — Actual data storage
🎯
Interview: "What is a jagged array?" — Rows of different lengths. Java supports this; C/C++ does not natively. Used in triangular matrices, Pascal's Triangle DP, adjacency lists.

New Expression Validity

ExpressionValid?Reason
new int[]❌ CEArray dimension missing

⚠️
Rule: You can leave trailing dimensions empty for jagged arrays, but you can NEVER skip a dimension in the middle — dimensions are filled left to right.

🅰️ 9. Static vs Dynamic Initialization
🅰️ Dynamic Initialization
  • Size known at runtime
  • Uses new keyword
  • Defaults assigned automatically
int[] arr = new int[5];
🅱️ Static Initialization
  • Values known at compile time
  • Size auto-calculated
  • Values directly assigned
int[] arr = {10, 20, 30};

⚠️ Separation Rule

Static Init — SeparationJava
int[] arr; arr = new int[3]; ✅ // Separate declaration + construction int[] arr; arr = {1,2,3}; ❌ // Static init MUST be same statement!

👻 11. Anonymous Arrays

Arrays without a reference variable — created on-the-fly, typically to pass directly into a method.

Anonymous Array SyntaxJava

🔀 12. Array Element Assignments

Case 1 — Primitive Arrays

Any type that can be widening-promoted to the declared type is allowed as an element.

Widening Promotion Chain: byte ──▶ short ──┐ ▼ char ──────▶ int ──▶ long ──▶ float ──▶ double
int[] Element AssignmentJava
int[] a = new int[5]; a[0] = 97; ✅ // int literal a[1] = 'a'; ✅ // char → int promoted byte b = 10; a[2] = b; ✅ // byte → int short s = 20; a[3] = s; ✅ // short → int a[4] = 10l; ❌ // long → int, loss of precision

Case 2 — Object Type Arrays

Declared type or any child class object is accepted.

Object[] and Number[]Java
Object[] a = new Object[3]; a[0] = new Integer(10); ✅ a[1] = new Object(); ✅ a[2] = new String("hello"); ✅ Number[] n = new Number[3]; n[0] = new Integer(10); ✅ // Integer extends Number n[1] = new Double(10.5); ✅ // Double extends Number n[2] = new String("hello"); ❌ // String does NOT extend Number
Object │ Number │ ┌─┬─┬─┬─┬─┐ I B S L F D │ │ │ │ │ │ Integer Byte Short Long Float Double

Case 3 — Interface Type Arrays

Interface ArrayJava
Runnable[] r = new Runnable[2]; r[0] = new Thread(); ✅ // Thread implements Runnable r[1] = new String("hello"); ❌ // String doesn't implement Runnable

🔄 13. Array Variable Assignments

Case 1 — Element Promotions ≠ Array Promotions

⚠️
Element-level promotion is NOT applicable at array object level.
A char value can promote to int, but char[] cannot be assigned to int[]!
PromotionValid?
char → int✅ Valid
char[] → int[]❌ Invalid
int → long✅ Valid
int[] → long[]❌ Invalid
double → float❌ Invalid (narrowing)
double[] → float[]❌ Invalid
String → Object✅ Valid
String[] → Object[]✅ Valid (Object arrays support this!)
String[] to Object[]Java
String[] s = {"A", "B"}; Object[] o = s; ✅ // Child type array → Parent type array (Object arrays)

Case 2 — Reference Reassignment (Not Copy)

ℹ️
When assigning one array to another, only the reference is copied — elements are NOT duplicated. Size doesn't matter; type must match.
Reference ReassignmentJava
int[] a = {10, 20, 30, 40, 50, 60, 70}; int[] b = {80, 90}; a = b; ✅ // a now points to b's array {80, 90} b = a; ✅ // sizes don't matter, types match

Case 3 — Dimension Must Match

Dimension MatchingJava
int[][] a = new int[3][]; a[0] = new int[4][5]; ❌ // 2D assigned to 1D slot a[0] = 10; ❌ // int assigned to int[] slot a[0] = new int[4]; ✅ // 1D int[] matches the slot
✅
Golden Rule: Types and dimensions must match. Sizes do NOT matter during array assignment.

🔁 Classic Loop Bug — i <= vs i <

Off-by-One Error (Interview Trap!)Java
String[] argh = {"A", "B"}; args = argh; // ❌ BUG: i <= args.length throws AIOOBE on i=2 for (int i = 0; i <= args.length; i++) { System.out.println(args[i]); // ❌ AIOOBE at i=2 } // ✅ CORRECT: i < args.length for (int i = 0; i < args.length; i++) { System.out.println(args[i]); // ✅ A, B } // ✅ SAFEST: enhanced for-each for (String s : args) { System.out.println(s); // ✅ A, B }
🎯
Interview Trap: "What happens with i <= arr.length?" — Always throws AIOOBE on the last iteration. Use i < arr.length or enhanced for-each.

All 3 Ways to TraverseJava

⚡ Quick Reference — Interview Cheat Sheet
✅ Always Remember
  • Arrays are objects → stored in Heap
  • Index: 0 to length-1
  • Access is O(1) — formula-based
  • Size fixed at creation
  • length is a field, not a method
  • Default: 0, false, null
  • Java supports Jagged Arrays
🚨 Common Mistakes
  • i <= length → AIOOBE (use <)
  • Size in declaration: int[5] arr → CE
  • Static init separate: arr = {1,2} → CE
  • char[] cannot assign to int[]
  • Middle dim skip: new int[3][][5] → CE
  • Unallocated jagged row → NPE
  • Anonymous with size: new int[3]{...} → CE
